# 04 — Reproducibility and code/data availability audit (NAR)

Audit date: 2026-10-18. Scope: the whole repository at `HEAD` of branch `claude/great-cori-opzfx7`
(remote `github.com/bkpaulvt-dev/Spatial`, working tree clean). Nothing except this file was changed.

**How it was tested.** Besides reading the code, the repository was exported with `git archive HEAD`
(exactly what a reader gets from a fresh clone, with no `data/`, `results/runs/`, `results/cache/` or
`results/emb/`) into a scratch directory, and the number, table and figure scripts were run there.

## Verdict

The **numbers, tables and supplement are reproducible** from the committed raw results: in a clean
export, `paper_numbers.py`, `paper_v2.py`, `stats_cluster_aware.py`, `coverage_matrix.py` and
`make_supplement.py` all ran without errors and rewrote 30+ outputs **byte for byte identical** to the
committed versions. `check_paper_numbers.py` passes (9/9 claims, 73/73 macros defined). Unit tests pass
(14/14). No secrets were found.

The **package is not yet NAR-ready**. The missing pieces are a top-level README and a single
entry point for the paper, an environment specification that covers the benchmarked methods, a
DLPFC download script with checksums, a licence and CITATION file, a Zenodo archive for the large
untracked intermediates (Figures 1 and 5 need them), and the GitHub URL and DOI in the manuscript.
Several of these contradict statements in `paper/main.tex` (see P0-3).

## Prioritised checklist

Legend: **P0** blocks submission (NAR policy or a false statement in the paper). **P1** a reviewer
will ask for it. **P2** hygiene. **P3** nice to have.
